# Walkthrough: Dynamic Visualizer Mode Synchronization & Unmapped Task HUD

## Summary of Completed Work
We resolved both visualizer challenges:
1. **Unmapped Task Map Suppression:** When unmapped tasks are dispatched (e.g. Option [1.2] *Full 6-Gesture Evaluation Suite*, [1.3] *ISO 15066 Safety Bubble Test*, or bench diagnostics), the pre-calibrated room map and waypoints are completely hidden. The visualizer instead features a dedicated **HRI & Touchless Gesture Teleoperation Cockpit** with a centered HD camera stage, a real-time canonical 6-gesture verification matrix with glowing neon detection indicators, active gimbal angles, and wheel kinematics.
2. **Dynamic Mission Mode Display:** Replaced the static `MODE 1: FOLLOW-TO-MAP SLAM` badge with a dynamic, reactive mode pill in the visualizer header that continuously reflects the exact mission launched from the menu (e.g., `MODE 1.2: 6-GESTURE TELEOP SUITE`, `MODE 1.1: FOLLOW-TO-MAP SLAM`, `MODE 2.1: CO-WORKER ESCORT`, `MODE 2.2: DEFENSE CAPSTONE PATROL`).

## Key Changes by Component

### 1. Visualizer Engine & Front-End Cockpit
- **[`scripts/web_map_visualizer.py`](file:///home/j/ros2_cognition_ws/scripts/web_map_visualizer.py):**
  - **CLI Flags Added:** `--mode <NAME>`, `--unmapped`, `--mapped`, `--view <gesture|slam|map>`.
  - **Multi-Channel Mode Synchronization:**
    * Polls `/tmp/amr_active_mode.json` and `/root/cognition_ws/current_mode.json` to detect menu dispatch events automatically.
    * Serves `POST /api/mode` endpoint for zero-latency HTTP mode switching.
    * Subscribes to ROS 2 topics `/cognition/mode`, `/cmd_vel`, `/cognition/gimbal_state`, `/servo_s1`, `/servo_s2`, and `/scan`.
  - **Unmapped HRI & Gesture Cockpit View:**
    * When `is_mapped == False`, the room map is not loaded or rendered.
    * Dedicated layout featuring large HD camera feed and an interactive **Canonical 6-Gesture Matrix**:
      - `🛑 STOP` (Open Palm): `/cmd_vel = 0.0 m/s` (Wheel Halt)
      - `👍 GO` (Thumbs Up): `+0.25 m/s` (Forward Transit)
      - `✌️ FOLLOW` (Peace Sign): Visual Servoing (Shadow Footsteps)
      - `👈 LEFT` (Point Left): `+0.40 rad/s` (Pivot CCW)
      - `👉 RIGHT` (Point Right): `-0.40 rad/s` (Pivot CW)
      - `👇 BACK` (Point Down): `-0.15 m/s` (Reverse Retreat)
    * Real-time active indicator highlights the detected gesture card with an emerald neon border, pulsing beacon, and exact confidence score.
    * Actuation telemetry: Gimbal Pan/Tilt servo angles, wheel linear ($v$) and angular ($\omega$) velocities, and LiDAR safety corridor clearance.
    * Suppresses mapped waypoint dispatch buttons (P1–P4) during unmapped tasks.
  - **View Toggle Support:** Added a `[📹 Gesture Cockpit] / [🗺️ Map View]` toggle button in the header so operators can switch perspectives anytime.

### 2. Master Demo Menu Mode Synchronization
- **[`scripts/master_demo_menu.py`](file:///home/j/ros2_cognition_ws/scripts/master_demo_menu.py):**

  - Writes local state `/tmp/amr_active_mode.json`, syncs to Docker container `/root/cognition_ws/`, and sends non-blocking `POST /api/mode` to port 8080.
  - Integrated into all dispatch functions:

    * `dispatch_interactive_gesture_hri()` -> `MODE 1.2: 6-GESTURE TELEOP SUITE` (unmapped, view=gesture)
    * `dispatch_safety_bubble_test()` -> `MODE 1.3: ISO 15066 SAFETY BUBBLE` (unmapped, view=gesture)
    * `dispatch_save_map()` -> `MODE 1.5: SAVE GENERATED 2D MAP` (unmapped, view=slam)
    * `dispatch_collaborative_escort_mapped()` -> `MODE 2.1: CO-WORKER ESCORT (AMCL)` (mapped, view=map)
    * `dispatch_capstone_patrol_preemption()` -> `MODE 2.2: DEFENSE CAPSTONE PATROL` (mapped, view=map)
    * `dispatch_waypoint_mission()` -> `MODE 2: <MISSION_NAME>` (mapped, view=map)
    * Diagnostics functions -> `MODE 3.x: ...` (unmapped, view=gesture)
