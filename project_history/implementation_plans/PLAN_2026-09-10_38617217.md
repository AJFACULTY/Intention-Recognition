## 3. The Gesture & Gimbal Blockers Identified

1. **`LEFT` & `RIGHT` Finger Geometry Bug:**
   In [src_nodes/gesture_node.py](file:///home/j/ros2_cognition_ws/src_nodes/gesture_node.py#L140-L188), the rule classifier previously evaluated `index_up = is_ext(8, 6, 5)`, which required $y_{tip} < y_{pip}$ (tip vertically above knuckle). When an operator points laterally to the left or right, $y$ does not decrease; instead, the lateral offset $\Delta x$ increases. We updated the rule to check lateral extension `d_index_ext > 1.35 * d_index_mcp`, but **this fix was only committed to Git on the laptop and was never pushed to the robot container!**
2. **The 2 Hz Person Detection Throttling Bug in `active_vision_node.py`:**
   In [active_vision_node.py:L208-L211](file:///home/j/ros2_cognition_ws/src_nodes/active_vision_node.py#L208-L211):
   ```python
   # Prioritize dedicated face target if recently active (<0.5s)
   if self.latest_target is not None and (time.time() - self.last_target_time) < 0.5:
       return
   ```
   Because `detection_callback` calls `target_callback(point)`, which updates `self.latest_target` and `self.last_target_time = time.time()`, **every single person detection throttled subsequent detections for 500 ms!** This artificially throttled person tracking down to 2 Hz. We will separate `self.last_face_time` from `self.last_target_time`.
3. **Target Loss FSM in `active_vision_node.py`:**
   When `target_callback` receives explicit loss ($z \le 0$), it did not set `self.latest_target = None`, causing `test_active_vision_logic.py` to fail transitioning to `MEMORY_HOLD`.
4. **Hand Jitter Decoupling:**
   When `hand_callback` in `active_vision_node.py` receives a hand target, it previously overrode person centering and yanked the camera up to the hand, causing camera jitter right as MediaPipe tried to classify fingers. We will ensure the gimbal smoothly holds the operator centered while permitting hand gestures to be read without jerking the camera.
