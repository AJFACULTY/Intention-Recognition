# Implementation Plan: Dynamic Visualizer Mode Adaptation & Unmapped Task HUD

## Problem Statement
Currently, when selecting unmapped tasks from the Master Demo Menu (such as Category [1.2] *Full 6-Gesture Evaluation Suite* or Category [1.3] *ISO 15066 Safety Bubble Test*):
1. The web visualizer (`:8080`) defaults to displaying a pre-calibrated static room map with waypoints (P1–P4) and simulated offline patrol, even though the selected task is an **unmapped** task where no prior map exists.
2. The mode badge in the top header is static, permanently displaying `MODE 1: FOLLOW-TO-MAP SLAM` regardless of what mission or task was launched.

## Proposed Solution
We will dynamically link the **Master Demo Menu** (`scripts/master_demo_menu.py`), the **Launch Pipelines** (`scripts/start_bench_pipeline.sh`, `launch/follow_to_map.launch.py`, `launch/master_robot.launch.py`, `scripts/start_nav2.sh`), and the **Cockpit Visualizer** (`scripts/web_map_visualizer.py`) through a multi-channel synchronization architecture (CLI flags, shared state file `/tmp/amr_active_mode.json`, REST API `POST /api/mode`, and ROS 2 topic `/cognition/mode`):

1. **When Unmapped Tasks are Selected (e.g. 1.2 Gesture Suite, 1.3 Safety Bubble, Bench Diagnostics)**:
   - `is_mapped = False`.
   - The static room map **does not appear**!
   - The visualizer switches to a high-visibility **HRI & Autonomous Teleoperation Cockpit**:
     * HD Camera Stream front and center with MediaPipe hand skeleton & YOLOv8 bounding box overlays.
     * **Interactive 6-Gesture Matrix** (STOP, GO, FOLLOW, LEFT, RIGHT, BACK) with real-time glowing status chips and confidence percentages that illuminate when that gesture is recognized.
     * **Active Vision Gimbal HUD** (Pan and Tilt angles, search/tracking state).
     * **Chassis Actuation & Kinematics** (Linear $v$, Angular $\omega$, motion state: PARKED / FORWARD / PIVOT / REVERSE).
     * **Safety Bubble Monitor** (Front corridor clearance and rear obstacle guard).
     * Mapped waypoints (P1..P4) and 4-Pt Patrol button are hidden.
2. **When Follow-to-Map SLAM is Selected (Option 1.1)**:
   - `is_mapped = False`, `view = 'slam'`.
   - The pre-calibrated room map is hidden.
   - The visualizer displays the real-time dynamic SLAM canvas as SLAM Toolbox explores and publishes new `/map` tiles.
   - The mode pill displays `MODE 1.1: FOLLOW-TO-MAP SLAM`.
   - Bottom dock displays a "💾 Save Active Map" action.
3. **When Mapped Tasks are Selected (Category 2: Escort, Capstone Patrol, Waypoints)**:
   - `is_mapped = True`, `view = 'map'`.
   - Displays the pre-calibrated facility map, AMCL particle cloud, dynamic costmaps, global plan, and waypoint buttons (P1 Home, P2 Center, P3 North, P4 East, 4-Pt Patrol).
   - Mode pill displays the exact mapped task (e.g. `MODE 2.1: CO-WORKER ESCORT`, `MODE 2.2: CAPSTONE PATROL`, `MODE 2.3: UNATTENDED PATROL`).
4. **Dynamic Header Mode Badge & View Switcher**:
   - The mode badge dynamically reflects the exact task being executed with coordinated color themes.
   - Operators can also manually toggle between the **Gesture & Vision Cockpit** and the **Spatial Map View** in the dashboard header.

## Proposed Changes

### 1. Visualizer Core & Cockpit UI
#### [MODIFY] [scripts/web_map_visualizer.py](file:///home/j/ros2_cognition_ws/scripts/web_map_visualizer.py)
- Support CLI arguments: `--mode <NAME>`, `--unmapped`, `--mapped`, `--view <gesture|slam|map>`.
- Add `self.is_mapped` and `self.active_view` state tracking.
- Do not assign pre-calibrated room map to `self.map_img` when `self.is_mapped == False`.
- In `_offline_simulation_loop`, only simulate waypoint patrol when `self.is_mapped == True`. When unmapped, simulate real-time gesture telemetry.
- Subscribe to `/cmd_vel`, `/cognition/gimbal_state`, `/cognition/mode`, and `/scan`.
- Add state-file polling (`/tmp/amr_active_mode.json`) to detect menu mode changes immediately.
- Add `POST /api/mode` endpoint to accept instant runtime mode and layout switches.
- Upgrade `DASHBOARD_HTML` and JavaScript:
  * Dynamic header badge `#mode-display` that updates text and theme from `/telemetry`.
  * Dedicated **Gesture & Autonomous Teleoperation Cockpit layout**:
    - Centralized HD camera feed.
    - 6-Gesture live card matrix with active gesture glowing highlights and confidence chips.
    - Gimbal servo angle gauges (Pan/Tilt).
    - Wheel velocity gauges ($v, \omega$).
    - Safety bubble corridor clearance indicator.
  * Conditional rendering: hides the map container and waypoint row during unmapped tasks.
  * Manual view toggle button: `[📹 Gesture Cockpit]` / `[🗺️ Map View]`.

### 2. Master Demo Menu Mode Synchronization
#### [MODIFY] [scripts/master_demo_menu.py](file:///home/j/ros2_cognition_ws/scripts/master_demo_menu.py)
- Implement `set_active_mission_mode(mode_name: str, is_mapped: bool, view: str = 'gesture')`:
  * Atomically writes `/tmp/amr_active_mode.json`.
  * If on Pi host, propagates `/tmp/amr_active_mode.json` to the Docker container (`yahboom_gesture`).
  * Sends non-blocking background HTTP `POST http://localhost:8080/api/mode` (and to robot IP if on workstation).
- Wire `set_active_mission_mode()` into every dispatch function:
  * `dispatch_collaborative_follow_slam()` -> `MODE 1.1: FOLLOW-TO-MAP SLAM` (unmapped, view=slam)
  * `dispatch_interactive_gesture_hri()` -> `MODE 1.2: 6-GESTURE TELEOP SUITE` (unmapped, view=gesture)
  * `dispatch_safety_bubble_test()` -> `MODE 1.3: ISO 15066 SAFETY BUBBLE` (unmapped, view=gesture)
  * `dispatch_save_map()` -> `MODE 1.5: SAVE GENERATED 2D MAP` (unmapped, view=slam)
  * `dispatch_collaborative_escort_mapped()` -> `MODE 2.1: CO-WORKER ESCORT (AMCL)` (mapped, view=map)
  * `dispatch_capstone_patrol_preemption()` -> `MODE 2.2: DEFENSE CAPSTONE PATROL` (mapped, view=map)
  * `dispatch_waypoint_mission(...)` -> `MODE 2.x: <MISSION_NAME>` (mapped, view=map)
  * Diagnostics options -> `MODE 3.x: <DIAGNOSTIC_NAME>` (unmapped, view=gesture)
- Call `set_active_mission_mode()` upon entering `menu_unmapped_environment()` and `menu_mapped_environment()`.
