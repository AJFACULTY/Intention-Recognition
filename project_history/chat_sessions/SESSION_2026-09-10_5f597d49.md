### Forensic Discovery: `/dev/video0` is an Empty Directory!

1. **Why this happened:** In Docker, if a container is configured to mount `-v /dev/video0:/dev/video0` while the camera is unplugged, **Docker automatically creates `/dev/video0` as an empty folder!**
2. **Why OpenCV failed:** When OpenCV tries to open camera index 0, it tries to read `/dev/video0`. Because `/dev/video0` is a directory (folder) instead of a camera device, OpenCV immediately fails with:
   `can't open camera by index`.
   Furthermore, because that folder exists, the Linux kernel is blocked from creating the real camera device node when you plug it in!

---

### The Fix (2 Steps):

#### Step 1: Remove the Bogus Directory on the Pi
On your **Raspberry Pi terminal** (`pi@raspberrypi:~ $`), run:

```bash
sudo rmdir /dev/video0 2>/dev/null || sudo rm -rf /dev/video0
```

#### What This Does:
Removes the empty dummy folder so Linux can freely assign `/dev/video0` to the real camera.

#### Step 2: Unplug and Re-plug the Camera USB Cable

### Why Did `camera_pub.py` Timeout When Manual `VideoCapture(0)` Succeeded?

In [camera_pub.py](file:///home/j/ros2_cognition_ws/src_nodes/camera_pub.py#L69), the code previously called:

On Linux UVC webcam drivers (`uvcvideo`), requesting an mmap buffer size of `1` **starves the kernel ring buffer queue**. The driver expects at least 2 to 4 buffers in the queue. Because `camera_pub.py` was locked in 10-second timeouts, it published only 1 frame every 10 seconds (0.1 FPS). `person_detection_node` and `gesture_node` were starved of images and accumulated `0:00` CPU seconds.
